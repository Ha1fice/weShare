# 自研多人协同在线文档（Word 类）技术选型报告

> 调研日期：2026-11-03。GitHub 数据来自 GitHub REST API（`api.github.com/repos/*`），npm 版本/许可证来自 npm Registry API，均于 2026-11-03（北京时间下午）实时抓取；许可证文本直接取自各仓库 HEAD 的 LICENSE 文件。无法核实处均已标注。

## 0. 结论（一句话）

**主选栈：Tiptap 3（ProseMirror 内核，MIT）+ Yjs 13 / y-prosemirror / Hocuspocus 4（全 MIT，自研服务端）+ mammoth.js 导入 / docx 9.x 导出（辅以 LibreOffice headless 做高保真兜底）+ 自研分页排版引擎（先做"分页展示"，再做真回流）。** 该组合许可证全绿（MIT/BSD/Apache/MPL，无 GPL 传染）、协同生态最成熟、可完全私有部署，唯一必须攻坚的硬骨头是分页排版引擎。

### 2.2 许可证精确边界（逐个核实）

- **Tiptap**：核心、`@tiptap/pm`、Starter Kit 及绝大多数扩展为 MIT（npm 实测 `@tiptap/core@3.32.2` license=MIT）。2025-06 官方把 Details、Emoji、DragHandle、FileHandler、InvisibleCharacters、Mathematics、TableOfContents、UniqueID 原 Pro 扩展转为 MIT 开源 [cite:7]。**仍付费的是产品捆绑**：Content AI、Collaboration 托管服务、Conversion（ConvertKit DOCX 导入导出，Beta）、Documents（Pages 分页）[cite:7][cite:8]。Pro 扩展中 Snapshots、Comments 及 AI Toolkit 部分功能需订阅 [cite:8]。
- **ProseMirror**：全部 MIT，稳定维护（低频但持续，npm 持续发版）。
- **Lexical**：MIT，Meta 维护，提交极活跃（抓取当日有推送）。
- **Slate**：MIT，但定位是"框架"非成品编辑器；协同绑定 slate-yjs（MIT，553★）最后推送 2024-06-20，已停更 [cite:1]。
- **Quill 2**：BSD-3-Clause；2.0.3 为最新版，仓库最后推送 2025-07-25，节奏明显放缓 [cite:1]。
- **Editor.js**：Apache-2.0，块状输出，天然不适合 A4 分页与 docx 保真。
- **CKEditor 5**：仓库 LICENSE 原文为 **GPL-2.0+ 或商业许可双轨** [cite:36]。关键点：实时协同、Track Changes、Comments、Revision History、**Pagination（分页）**、**Word 导入/导出**、多级列表全部是 Premium 商业功能 [cite:10][cite:11][cite:12][cite:13]。用 GPL 版自研等于所需功能全部缺失；用商业版则回到"许可证受制于人"，与题设战略冲突。
- **TinyMCE**：许可证边界为 **v5=LGPL-2.1，v6=MIT，v7（2024-03-20）起改为 GPL-2.0+/商业** [cite:2][cite:3][cite:4][cite:5]；当前 8.x 自托管必须配置 license_key 二选一 [cite:6]。MIT 的 v6 已停止支持，不构成可用选项。
- **BlockNote**：LICENSE 原文：核心 MPL-2.0（可闭源商用，改动需开源），`packages/xl-*`（`@blocknote/xl-*`）为 GPL-3.0，另有商业许可 [cite:35]。产品形态是 Notion 式块编辑器，与 A4 分页目标不符。
- **Milkdown**：MIT，Markdown 优先，协同走 Yjs [cite:33][cite:34]，但 Word 级排版扩展空间有限。

### 2.4 扩展成本与长文档性能

- **扩展成本**：Tiptap/ProseMirror 的 Schema+NodeView+Decoration 体系最适合自定义"脚注、批注锚点、修订标记、分页框"等一等公民节点；Lexical 的 Node 类体系次之但文档模型自由度也高；Quill/Editor.js 的固定模型扩展复杂结构成本高。
- **长文档性能**：ProseMirror 为全量 DOM 渲染，超长文档需自行做虚拟化/分块渲染；第三方对比称 Lexical 在 5,000+ 节点文档按键延迟比 ProseMirror 低 20–40%（厂商无关性存疑，仅作方向性参考）[cite:32]。**两者都必须在 PoC 中用真实中文长文档实测**（见 §7 PoC-3）。
- **中文排版**：两者均基于 contenteditable，需处理 CJK 输入法合成、行尾避头尾（`line-break: strict`）、中文标点后压缩；ProseMirror 对 IME 的处理经过大量生产验证（腾讯、字节等中文产品广泛使用），此项 Tiptap 略优。

## 3. 协同层选型

### 3.1 Yjs + y-prosemirror + Hocuspocus 是最优解

- **许可证全绿**：yjs（MIT，LICENSE 原文确认 [cite:38]，23,020★，2026-11-02 有推送）、y-prosemirror 1.3.7（MIT）、@hocuspocus/server 4.8.0 与 @hocuspocus/provider（MIT，Hocuspocus 4 于 2026-05 发布 stable [cite:40]）、y-indexeddb 9.0.12（MIT）、y-protocols（MIT）。
- **CRDT 天然适配需求**：无中心定序服务器即可合并并发编辑，离线编辑后重连自动合并（配合 y-indexeddb 本地持久化，官方文档明确支持离线场景 [cite:26][cite:27]）。
- **Hocuspocus 服务端能力**：WebSocket 网关 + 文档级钩子（鉴权、持久化、只读控制）；Database/SQLite 扩展做服务端持久化，Redis 扩展做水平扩展（多实例同步，Redis 仅同步不持久，持久用 Database 扩展）[cite:23][cite:24]。
- **对比备选**：Automerge 2（MIT，6,710★，活跃）也是优秀 CRDT，但 ProseMirror 绑定成熟度与社区案例显著少于 y-prosemirror；prosemirror-collab（官方 OT 模块）需要自研中心定序服务器与变换逻辑，工作量大于 CRDT 路线，不建议。

### 3.2 与 Tiptap 商业部分的边界（重要）

| 组件 | 性质 | 说明 |
|---|---|---|
| @tiptap/extension-collaboration / -cursor | **MIT 免费** | 只是 y-prosemirror 的封装，npm 实测 license=MIT |
| Hocuspocus（自托管） | **MIT 免费** | 全部服务端能力开源 |
| Tiptap Cloud / Collab 托管 | 商业 | 不用，私有部署自建 |
| Comments 扩展 | 付费订阅 [cite:8] | **自研**（mark + Y.Map 侧存储，见 §6.3） |
| Snapshots/History 扩展 | 付费订阅 [cite:8][cite:25] | **自研**（Y.Doc 快照，见 §3.3） |
| Pages 分页（@tiptap-pro/extension-pages） | 付费 [cite:20][cite:21] | **自研**（见 §5），可参考其设计 |
| ConvertKit（DOCX 转换，Start 计划 Beta） | 付费 [cite:8] | 用开源链路替代（见 §4） |

结论：**协同核心链路 0 商业费用**；付费项全部有明确的自研替代路径。

### 3.3 服务端持久化、离线合并、版本快照

- **持久化**：Hocuspocus `onStoreDocument` 钩子把 `Y.encodeStateAsUpdate` 二进制写入 PostgreSQL/MySQL（官方 Database 扩展即此模式 [cite:24]）；建议同时落一份"展开后的业务 JSON/HTML 镜像"供搜索与只读渲染。
- **离线合并**：浏览器端 y-indexeddb 缓存 + HocuspocusProvider 断线重连后自动交换增量（CRDT 语义保证收敛）[cite:26][cite:27]。
- **版本快照**：官方 Snapshot 扩展收费 [cite:25]，自研方案：① 定时/按里程碑对 Y.Doc 做 `encodeStateAsUpdate` 快照存库；② 版本对比用 Yjs 的 state vector 差分或展开后 JSON diff；③ 定期 `Y.mergeUpdates` + 开启 gc 压缩历史，控制文档膨胀。
- **权限控制**：Hocuspocus `onAuthenticate` 钩子做文档级鉴权，`onLoadDocument` 时按角色注入只读标记（Yjs awareness + 编辑器 `editable=false`）。

## 4. docx 保真链路

### 4.1 各组件能力矩阵（均为实测/官方文档口径）

| 组件 | 许可证/活跃度 | 能做什么 | 不能做什么 |
|---|---|---|---|
| **mammoth.js** 1.13.0（BSD-2-Clause，6,337★，2026-10 有推送）[cite:15][cite:16] | .docx → **语义 HTML**：标题、列表、表格（仅结构，边框等格式忽略）、脚注/尾注、图片、粗斜体/下划线/删除线/上下标、超链接、换行、文本框（拍平）、**批注（README 明确列出）** [cite:16]；支持自定义 styleMap | 不还原视觉格式（字体/颜色/字号）、无页眉页脚、无分页、无编号细节、无域代码 |
| **docx-preview**（docxjs）0.4.1（Apache-2.0，2,134★）[cite:14] | 浏览器内**高保真只读渲染** .docx：自定义样式、列表、表格（边框/底纹/表头行）、图片、超链接、**页眉/页脚、脚注/尾注、批注（实验性）、分节** [cite:14] | 只读，不可编辑；不能作为编辑模型 |
| **docx（dolanmiu）** 9.15.1（MIT，5,981★，2026-11-02 有推送）[cite:17] | **生成** .docx：段落/表格/图片/超链接/页眉页脚/页码/脚注尾注/目录/编号/书签/域/数学公式，v9 文档含 **Comments（批注）与 Change Tracking（修订）** 章节及 `docx/html`（HTML→docx）、Patcher 模板套改、`docx/layout` 页码估算 [cite:17][cite:18] | 非"所见即所得"排版引擎；复杂域代码/艺术型排版需手写 XML 补丁 |
| **html-docx-js**（MIT，1,155★，**停更于 2021-10**） | HTML→docx（altChunk 整体嵌入） | 保真差、无维护，**弃用** |
| **LibreOffice headless**（MPL-2.0 [cite:29]，服务端部署） | 全保真 docx↔docx/pdf/odt 转换，可做导入预处理、导出兜底、PDF 导出 | 体积大（数百 MB）、转换非实时、无法承载在线编辑 |
| **Pandoc**（**GPL-2.0**，46,790★）[cite:30] | docx↔markdown/html，脚注/表格/引用好；`--reference-doc` 可继承样式表、页边距、页面尺寸、页眉页脚 [cite:30] | GPL 传染：必须独立进程调用且不分发捆绑版；不还原视觉排版 |

### 4.2 推荐的导入/导出路径

```
导入：.docx ──mammoth.js(styleMap 定制)──▶ 语义 HTML ──▶ ProseMirror Schema
        └─（并行）docx-preview 渲染"原文预览"视图，供用户对照（保真兜底）
        └─（可选）复杂文档先过 LibreOffice headless 规整化
导出：ProseMirror JSON ──自研映射器──▶ docx 9.x 声明式对象 ──▶ .docx
        └─ 批注/修订走 docx 的 Comments / Change Tracking API [cite:17]
        └─ PDF 导出：LibreOffice headless（或打印样式 + 浏览器打印）
```

### 4.3 保真缺口与必须自研项

| 要素 | 导入 | 导出 | 自研必要性 |
|---|---|---|---|
| 分页/分页符 | 丢失 | 需自研分页引擎产出分页信息后写入 | **必须自研**（§5） |
| 页眉/页脚 | mammoth 丢失；docx-preview 可渲染 | docx 库支持 | 需自研"节/页眉页脚"数据模型 |
| 样式表 | mammoth 仅语义映射 | docx 库支持样式定义 | 需自研双向 styleMap 管理 |
| 多级编号/编号重启 | 部分丢失 | docx 库支持 numbering 配置 | 需自研编号状态同步 |
| 表格 | 结构保留、格式丢失 | 基本保真 | 中等自研（边框/合并/宽度） |
| 图片 | 保留 | 保留 | 低 |
| 脚注/尾注 | 保留 [cite:16] | 支持 [cite:17] | 需自研脚注节点模型 |
| 批注 | mammoth 支持读取 [cite:16] | docx 9.x Comments [cite:17] | 需自研批注锚点模型 |
| 修订痕迹 | 不支持 | docx 9.x Change Tracking [cite:17] | 二期自研 |
| 域代码（TOC/PAGE 等） | 丢失 | 部分支持（目录/页码域） | 按需自研 |

## 5. 分页排版选型

| 方案 | 许可证 | 评估 |
|---|---|---|
| paged.js 0.4.3（MIT，1,559★，2026-10 有推送） | MIT | CSS Paged Media 填充器，面向**打印/生成**（分页渲染静态 HTML 成 PDF 形态），不是交互式编辑排版引擎；编辑态实时回流不适用。可用于"导出预览"辅助 |
| Vivliostyle（**AGPL-3.0**，801★）[cite:28] | AGPL-3.0 | 排版能力强，但 AGPL 对闭源商业产品是硬伤，官方 FAQ 亦确认 AGPLv3 [cite:28]；**排除**（除非接受开源义务或购买商业授权） |
| Tiptap Pages（@tiptap-pro/extension-pages + pagebreak） | **商业付费** [cite:20][cite:21] | 现成的分页编辑层（页面边界、页面格式、页眉页脚、分页符、缩放），可买断时间，但与"开源孵化"战略冲突，且长期订阅成本不可控；**可作设计参考与紧急备胎** |
| 社区开源 tiptap-a4-pagination 0.2.0（MIT，2026-10-22 首发，周下载 ~108） | MIT | 太新太小，不可作为基座；但验证了"ProseMirror 上做 A4 分页"的技术路线（页边距、表格按行拆分跨页、表头重复）[cite:19] |
| **自研分页引擎** | 自有 | **推荐**。在 ProseMirror 之上做"测量-切分"层：以块级节点为粒度测量高度、按 A4 可用高度切分、表格/列表允许跨页断行、页眉页脚/页码为独立渲染层 |

**推荐路径（两阶段，控制风险）**：
1. **阶段一（分页展示）**：内容仍连续编辑，渲染层按页面高度插入"页面视觉框"（页边距、页间留白、页码占位、分页符节点），表格整块不跨页。工作量约为分页引擎的 40%。
2. **阶段二（真回流分页）**：块内/表格行级跨页切分、页眉页脚按节配置、编辑时增量重排（只重排受影响页）、与协同光标兼容。这是全项目最大技术风险点，必须尽早 PoC（§7 PoC-3）。

## 6. 推荐结论

### 6.1 主选栈（精确到包名/版本方向）

| 弃用 | html-docx-js（停更）、Pandoc（GPL，仅当确需且可隔离时备选）、Vivliostyle（AGPL） | — |

### 6.2 备选栈

- **备选 A（性能优先）**：Lexical 0.53.x + @lexical/yjs + Hocuspocus。若 PoC 证明 ProseMirror 在 10 万字级文档不达标则切换；代价是协同绑定与中文 IME 生态验证较少。
- **备选 B（预算换时间）**：CKEditor 5 商业许可（含协同/修订/分页/Word 导入导出）[cite:10][cite:11]。与"基于开源组件长期孵化"的战略冲突，仅当管理层愿意接受供应商锁定与按量计费时考虑。
- **分页紧急备胎**：采购 Tiptap Pages 商业授权先上线，再逐步自研替换。

### 6.3 分层架构

```
┌─ L6 产品层：权限（文档/空间级）、版本历史 UI、导出中心
├─ L5 批注/修订层：批注 mark（稳定锚点 ID）+ Y.Map 侧存储；修订（二期）基于 mark + 快照 diff
├─ L4 分页渲染层：页面测量/切分引擎、页眉页脚/页码渲染、缩放（自研，先展示后回流）
├─ L3 导入导出管道：mammoth 导入 → Schema；Schema → docx 9.x 导出；LibreOffice 兜底；docx-preview 原文预览
├─ L2 协同层：Yjs Y.Doc（Y.XmlFragment 承载文档 + Y.Map 承载批注/元数据）
│    ├─ 客户端：y-prosemirror 绑定 + y-indexeddb 离线 + HocuspocusProvider
│    └─ 服务端：Hocuspocus（鉴权/持久化/只读控制）+ PostgreSQL + Redis
└─ L1 编辑器内核 + 文档模型：Tiptap 3 / ProseMirror Schema
     （自定义节点：脚注引用/内容、批注锚点、分页符、页码域占位）
```

关键设计决策：
- **文档模型以 ProseMirror Schema 为唯一事实源**，Yjs 只承载同步；导出/快照都从 Schema 展开。
- **批注不进文档树正文**：用带 UUID 的 mark 锚定范围，批注内容/线程存 Y.Map，规避 CRDT 合并时的结构冲突（Tiptap UniqueID 扩展已 MIT，可用于节点稳定 ID [cite:7]）。
- **版本历史自研**：Y.Doc 定时快照 + 命名版本 + 展开 JSON diff 对比，绕开付费 Snapshot 扩展 [cite:25]。

## 7. 三个可验证 PoC（含验收标准）

### PoC-1 协同收敛与离线重连（1–1.5 人周 × 2 人）
- 内容：Tiptap + y-prosemirror + Hocuspocus（本地 Docker，PostgreSQL 持久化）；两个浏览器 + 一个弱网模拟客户端。
- 验收标准：
  1. 3 客户端同段并发编辑 5 分钟，最终三端文本逐字节一致；
  2. 断网客户端离线编辑 ≥20 处后重连，无需人工干预自动合并成功；
  3. 杀掉 Hocuspocus 进程重启，客户端自动重连且内容无损（从 DB 恢复）；
  4. 远程光标/选区实时可见（awareness）；
  5. 局域网内输入→远端呈现延迟中位数 < 100ms。

### PoC-2 docx 往返保真（1.5–2 人周 × 2 人）
- 内容：准备 3 份代表性 .docx（含：标题 3 级、有序/无序+嵌套列表、带合并单元格表格、图片、超链接、脚注、批注、页眉页脚、分页符）；mammoth 导入 → Tiptap 编辑 → docx 9.x 导出；同时用 docx-preview 渲染原文。
- 验收标准：
  1. 导入侧：标题层级、列表结构、表格结构、图片、链接、脚注 6 类元素 100% 进入编辑器模型；
  2. 导出侧：用 Word/WPS 打开导出文件不报错，上述 6 类元素 + 批注在 Word 中可见；
  3. 输出书面《保真缺口清单》：页眉页脚、分页、样式表、编号重启、域代码逐项标注"已支持/自研项/不支持"；
  4. 往返（导入→导出→再导入）后文档结构 diff 为空（允许视觉格式差异）。

### PoC-3 分页排版与长文档性能（2–3 人周 × 2 人）
- 内容：在 Tiptap 上实现最小分页渲染层：A4 页面框（210×297mm）、页边距（默认 2.54cm）、页码占位、按块高度切页、表格整块跨页策略；构造 10 万字 + 50 张图 + 20 个表格的中文测试文档。
- 验收标准：
  1. 分页位置与 Word 打印预览比对，抽样 20 页中 ≥18 页一致（±1 行容差）；
  2. 文档任意位置输入，按键到渲染完成 P95 < 100ms（中端笔记本、Chrome）；
  3. 两人协同编辑该长文档 10 分钟，分页重排不导致光标/滚动位置错乱；
  4. 中文避头尾正确（抽样 50 个行尾无违规标点）；
  5. 结论物：《分页引擎详细设计 + 阶段二工作量修正值》，用于校准 M3 估算。
