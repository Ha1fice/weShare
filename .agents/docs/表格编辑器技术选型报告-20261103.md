# 在线协同表格编辑器技术选型报告（自研私有部署 · 表格侧）

- 报告日期：2026-11-03（所有 GitHub API / npm registry / 官网数据均于当日实际抓取，下文逐项标注来源）
- 场景约束：公司服务器/纯局域网私有部署、Web 端、多人实时协同、闭源商业产品、长期对标腾讯在线文档
- 明确排除：ONLYOFFICE / Collabora 等服务端渲染方案

---

## 1. 结论（一句话主选栈）

**主选栈：以 Univer 开源 core（`dream-num/univer`，Apache-2.0，v1.3.x）为网格渲染/数据模型/公式引擎底座，协同层用 Yjs（MIT）包装 Univer mutation 自研（或预算允许时直接采购 Univer Business 授权换取现成协同与转换服务），.xlsx 导入导出用「SheetJS CE（Apache-2.0）解析 + ExcelJS（MIT）写出 + 自研样式映射层」的管道自研；公式引擎只用 Apache/MIT 系（Univer engine-formula 优先），坚决不引入 HyperFormula（GPL-3.0）。**

备选栈：fortune-sheet（MIT）作为 Univer 商业化边界恶化时的整体降级方案；AG Grid Community（MIT）仅作为大数据虚拟滚动的工程参考，不作为表格内核。

核心判断：
1. **「Univer 开源 core + 自研协同」成立，但要清醒**：开源版覆盖网格渲染、数据模型、公式、条件格式、数据验证、筛选排序、数字格式、批注；而**图表、透视表、.xlsx 导入导出（转换）、实时协同全部在商业版**（官方定价页 FAQ 原文确认 [cite:15]）。自研路线等于自己补齐商业版的核心价值，预计占总工作量 50% 以上。
2. **Univer 是当前唯一值得押注的开源底座**：22,859 star、Apache-2.0、当日（2026-11-03）仍有提交、最新 release v1.3.1（2026-11-02 发布）、73 位贡献者 [cite:1][cite:23]。Luckysheet 已归档且 README 明示不再维护 [cite:2][cite:24]，fortune-sheet 约 11 个月无提交 [cite:3]，其余候选要么是数据网格（非表格语义）、要么维护停滞。
3. **采购 Univer Business 是合法的加速器**：起价 $99/月或 $1,000/年（25 协同连接、500 次导出/月），**支持完全离线私有部署、运行时不联网校验、无遥测** [cite:15]。对纯局域网部署友好。注意：授权绑定一个主域名，**部署到不同客户的服务器需要单独授权**（若未来对外售卖私有化需计入成本模型）[cite:15]。

## 3. Univer 深度核实（重点项）

### 3.1 Apache-2.0 覆盖范围
- 覆盖公共仓库全部代码（上节所列 60+ 个包），可商用、可修改、可随闭源产品分发，保留版权声明即可 [cite:1][cite:15]。
- 官方 FAQ 原文："The open-source core is licensed under Apache-2.0 and can be integrated into and distributed with your product or open-source project under that license." [cite:15]
- **不覆盖**：商业版 SDK（Web SDK 的图表/打印等能力、Server SDK 的协同与文件转换、AI SDK），这些通过授权文件私有分发 [cite:14][cite:15]。

### 3.2 开源版 vs 商业版能力边界（官方原文）
> "The commercial edition includes the complete Web SDK, Server SDK, and AI SDK, with features such as **charts, pivot tables, Office file conversion, and real-time collaboration**." [cite:15]

| 能力 | 开源版 | 商业版 |
|---|---|---|
| 网格渲染/虚拟滚动（Canvas） | ✅ engine-render | — |
| 公式引擎（400+ 函数级别） | ✅ engine-formula（Apache-2.0）[cite:14] | — |
| 单元格样式/数字格式/合并/冻结 | ✅ | — |
| 条件格式/数据验证/筛选排序 | ✅（均有独立开源包）[cite:14] | — |
| 批注/评论 | ✅ sheets-note / sheets-thread-comment [cite:14] | — |
| **图表** | ❌ | ✅ [cite:15] |
| **透视表** | ❌ | ✅ [cite:15] |
| **.xlsx 导入导出/格式转换** | ❌（exchange 不在公共 npm）[cite:14] | ✅（导入 XLS/XLSX/CSV/TSV，导出 XLSX/CSV/TSV）[cite:15] |
| **实时协同（冲突处理/光标选区/历史）** | ❌（collaboration 不在公共 npm）[cite:14] | ✅ Server SDK 提供 [cite:15] |
| 打印 | ❌ | ✅ [cite:15] |

### 3.3 Pro 授权价格与私有部署（2026-11-03 抓取 [cite:15]）
| 档位 | 价格 | 容量 | 关键条款 |
|---|---|---|---|
| Free Trial | $0 | 3 协同连接、10 次导出/月、带水印、导入不限 | 仅限评估 |
| Business | **$99/月起，或 $1,000/年起**（1–12 个月期，不自动续费） | 25+ 协同连接、500+ 次导出/月 | 含完整 Web/Server/AI SDK；**1 个协同服务实例 + 1 个导入导出服务实例**；1 个主域名及其全部子域名 |
| Enterprise | 定制报价 | 连接与导出均不设限 | 分布式/多实例/高可用部署必须 Enterprise |

私有部署关键事实 [cite:15]：
- **可完全离线运行**："Univer can run entirely in your own environment without internet access. Commercial licenses are configured and validated locally, with no online license verification or telemetry reporting at runtime." —— 对纯局域网环境是硬性利好。
- 官方推荐配置（参考负载：约 1 万填充单元格、10% 公式）：250 并发协同 = 导入导出服务 4C/8G ×1 + 协同服务 4C/8G ×1。
- **域名绑定**：一个授权覆盖一个主域名+子域名；部署到其他主域名（**含客户自有机房的私有化交付**）需另行授权，除非书面约定。→ 若产品未来卖给多个客户做私有化，授权成本要按客户数建模。
- 连接数计费口径：只有参与协同编辑并提交变更的实例计数；只读、单机编辑不计数；2 分钟无提交释放连接。

### 3.4 二次开发难度评估
- 架构：TypeScript + 依赖注入 + 插件化（每个功能都是 plugin），mutation/command 模式（类 OT 操作流）——**这套设计本身就是为协同准备的**，是自研协同层可依附的关键。
- 学习曲线：中偏高。DI 框架、插件生命周期、mutation 体系需要 2–4 周上手期；文档较完整（中英），社区 73 贡献者、148 个 open issue，响应活跃 [cite:1][cite:23]。
- 风险：版本迭代快（已到 1.3.x），API 仍有破坏性变更可能 → 锁定版本 + 维护 fork。

| 引擎 | 许可证（实测） | 形态 | 维护状态 | 对闭源私有部署产品 |
|---|---|---|---|---|
| **@univerjs/engine-formula** | Apache-2.0 [cite:14] | 与 Univer 深度集成，支持 Worker | v1.3.1，2026-10-30 发布 [cite:14] | ✅ **首选**，零额外成本 |
| formulajs | **MIT**（原始 LICENSE 文件实测确认）[cite:11] | 纯函数库（约 400+ 函数实现），无解析器/依赖图 | 2026-10-01 有提交 [cite:11] | ✅ 安全，可作函数语义参考/补丁源 |

| HyperFormula | **GPL-3.0（开源版）**，商用需购买商业授权（双授权）[cite:10][cite:16][cite:17] | 独立引擎，~400 函数，v3.5.0（2026-10-09）[cite:17] | ❌ **禁用**：GPL-3.0 强传染，闭源产品集成即触发开源义务；除非向 Handsontable 购买商业授权（价格不公开，需询价）[cite:16] |

## 5. 协同方案三路线对比

| 路线 | 内容 | 难度 | 工期（2–4 人） | 适用性 |
|---|---|---|---|---|
| A：采购 Univer Server SDK | 官方 OT 协同：冲突处理、光标/选区同步、版本历史、Worktree，开箱即用 [cite:15] | 低（集成 2–4 周） | 集成 0.5–1 人月 + $99/月起授权 [cite:15] | 想快速上线、接受年费与域名绑定条款时首选；纯局域网离线部署官方支持 [cite:15] |
| B：**Yjs 包装 Univer mutation（推荐自研路线）** | Univer 的变更本身是细粒度 mutation（单元格级操作流），将 mutation 映射进 Y.Map（每 sheet 一个 Y.Map，key=单元格地址）经 y-websocket/自研 WS relay 同步；awareness 协议做光标/选区 | 中-高 | MVP 2–3 人月，生产级（离线重连、冲突收敛、undo/redo 协同）4–6 人月 | 坚持全自研、零授权费、长期可控；Yjs 为 MIT、CRDT 收敛性有数学保证 |
| C：完全自研 OT/CRDT | 自造操作变换/状态机 + 中心定序服务器 | 极高 | 6–12 人月起，且正确性验证成本巨大 | 除非有分布式系统专职人才，否则不建议 |

大数据量下的冲突粒度设计（路线 B 要点）：
- **单元格级 LWW + 字段级合并**：值冲突取逻辑时钟最大者；样式类属性（字体/边框/填充）拆为独立字段分别 LWW，避免"改字体覆盖他人填值"。
- **结构性操作（插删行列、合并/拆分）走全局定序**：这类操作影响坐标映射，必须串行化（服务器定序或 Yjs 的 Y.Array 位置编码），不能 LWW。
- **分片**：按 sheet/行块组织 Y.Doc，避免单 Doc 过大；10 万行级文档用快照+增量日志而非全量 CRDT 历史。
- **离线重连**：Yjs 天然支持（状态向量增量同步），重连后自动收敛；配合服务端快照做冷启动加速。

## 6. .xlsx 导入导出保真能力边界

库能力矩阵（许可证与状态均为 2026-11-03 实测）：

| 库 | 许可证/状态 | 样式 | 合并单元格 | 条件格式 | 数据验证 | 图表 | 公式/缓存值 |
|---|---|---|---|---|---|---|---|
| SheetJS CE | Apache-2.0；仓库已迁至 git.sheetjs.com，GitHub 镜像 2024-04 起停更；npm `xlsx` 停在 0.18.5 [cite:8][cite:21][cite:26] | **❌ 不支持写出样式**（样式为 Pro 付费能力）[cite:22] | ✅ | ❌ | 部分 | ❌ | 读公式文本 ✅ / 不求值 |
| ExcelJS | MIT；**最后提交 2025-01-21，约 22 个月无更新，824 个 open issue** [cite:7] | ✅ 读写 | ✅ | 部分（有限） | ✅ | ❌ | 写公式+缓存值 ✅（不求值） |
| xlsx-populate（dtjohnson） | MIT；最后提交 2024-03-12，约 32 个月无更新 [cite:9] | ✅ | ✅ | ❌ | ❌ | ❌ | 写公式 ✅ |
| Univer Server SDK（商业） | 私有授权 [cite:15] | ✅（官方目标为保真转换，官方提示不支持的元素会被丢弃，需用真实文件验证）[cite:15] | ✅ | ✅ | ✅ | 导入可识别，导出以官方实测为准 | ✅ |
| LibreOffice headless | **MPL-2.0**（文件级弱 copyleft；作为独立进程调用对闭源产品安全） | 高 | ✅ | ✅ | ✅ | ✅ | ✅ |

关键边界判断：
1. **没有任何一个开源 JS 库能写出 xlsx 原生图表**。图表保真只有两条路：(a) 自研 OOXML chart part 的 XML 透传/生成（工作量大）；(b) LibreOffice headless 辅助转换（部署包 500MB+，转换保真度对复杂文件不稳定，且引入进程管理成本）。建议 MVP 阶段图表降级为「应用内 ECharts 渲染 + 导出时降级为图片/数据表」，把原生图表保真列为长期项。
2. **公式缓存值**：导出时必须写出 `<v>` 缓存值，否则 Excel 打开显示 0。方案：用 Univer engine-formula 在 Node 侧 headless 计算后回填（Apache-2.0 允许）。
3. **推荐管道**：导入用 SheetJS CE（解析健壮性业界最强、Apache-2.0 [cite:21]）→ 统一单元格模型（CSF）→ Univer 数据模型；导出用 ExcelJS（样式/合并/验证写出能力最全）+ 自研样式映射层。ExcelJS 停更的对策：IO 层做接口抽象，可切换 xlsx-populate 或自维护 fork。
4. **保真度分级验收**（写进合同/里程碑）：L1 数据+公式 100%；L2 样式/合并/数字格式 ≥90%；L3 条件格式/数据验证/批注 尽力保留；L4 图表/透视表/图片 降级处理并明示。

## 7. 推荐架构（分层）

```
┌─────────────────────────────────────────────────────────┐
│ 6 图表层：应用内 ECharts 渲染 + 自研图表数据模型；          │

│ 4 协同层（自研）：Yjs（Y.Map/sheet + awareness 光标选区）   │
│   + WebSocket relay + 快照/操作日志 + 离线重连              │
│   ［或：Univer Server SDK 商业替代］                       │
├─────────────────────────────────────────────────────────┤
│ 3 公式引擎：@univerjs/engine-formula（Apache-2.0, Worker） │
├─────────────────────────────────────────────────────────┤
│ 2 数据模型：@univerjs/core + sheets（Workbook 模型 +       │
│   mutation 操作流）→ 版本历史/权限挂接点                    │
```

| **合计** | | **13–21 人月** | 2 人 ≈ 8–12 个月；3 人 ≈ 6–8 个月；4 人 ≈ 4.5–7 个月（含联调，不含全职 QA） |

估算校准依据：
- 若不用 Univer 而手写 Canvas 网格+公式引擎达到其现状，行业经验约 12–20 人月——Univer OSS 相当于省下这部分，这是选它的最大理由。
- 协同与 xlsx 保真无开源现成方案，是区间上限的主要来源；若中途采购 Univer Business（$1,000/年起 [cite:15]），M2+M3 可压缩 3–6 人月，需与授权成本、域名绑定条款权衡。
- 2 人团队风险偏高（协同层攻坚期建议 ≥3 人）。

## 9. 主要风险与规避

| 风险 | 等级 | 规避 |
|---|---|---|
| Univer 继续把开源能力迁入商业版（边界蠕变） | 高 | 锁定版本 + 维护 fork；Apache-2.0 保证已发布代码的永久使用权；用 fortune-sheet 作整体降级预案 |
| 协同复杂度失控（undo/redo、结构操作、离线） | 高 | MVP 只做单元格级 LWW + 结构操作服务器定序；不做 Google Docs 级全文档 OT；PoC-2 先行验证 |
| xlsx 长尾保真无底洞 | 高 | 分级验收（L1–L4）写进里程碑；建真实文件样本库持续回归；LibreOffice（MPL-2.0，独立进程调用对闭源安全）作兜底转换 |
| ExcelJS 停更（约 22 个月无提交 [cite:7]） | 中 | IO 层接口抽象，可切 xlsx-populate/fork/自研写出器 |

| 团队规模不足 | 中 | 建议 3–4 人；2 人时先砍图表与历史，保单机+协同 MVP |
| 未来对外售卖私有化时的 Univer 授权成本（如采购路线） | 中 | 授权按主域名计，客户侧部署需单独授权 [cite:15]；自研路线不受此限 |

## 10. 三个可验证 PoC（M0，约 1 个月）

### PoC-1：Univer OSS 集成与性能基线
- 内容：集成 `@univerjs/core + sheets + sheets-ui + engine-render + engine-formula + sheets-conditional-formatting + sheets-data-validation + sheets-filter + sheets-numfmt`（全部 1.3.x，Apache-2.0），纯离线环境运行。
- 验收标准：
  1. 10 万行 × 50 列空表 + 1 万公式单元格，滚动帧率 ≥ 45fps（目标 55fps），首屏渲染 < 2s（中端笔记本）；
  2. 修改 1 个被 1,000 个公式依赖的单元格，重算完成 < 500ms；
  3. 断网环境（纯局域网）全功能可用，无任何外部请求。

### PoC-2：协同闭环（Yjs + mutation 桥）
- 内容：两个浏览器 + 一个 Node relay（y-websocket 或自研 WS），将 Univer mutation 映射进 Y.Map；awareness 同步选区。
- 验收标准：
  1. 两端同时编辑同一单元格，释放后收敛一致（单元格级 LWW），3 次重复实验 0 数据丢失；
  2. 一端断网 30 秒内持续编辑，重连后 5 秒内自动收敛，无冲突弹窗；
  3. 光标/选区实时可见；1 万单元格文档冷启动同步 < 3s；
  4. 插入/删除行在并发编辑下坐标正确（验证结构操作定序方案）。

### PoC-3：xlsx 往返保真
- 内容：准备 10 个真实文件（覆盖：多 sheet、样式、合并、冻结、条件格式、数据验证、公式、图表、图片、大表），走「SheetJS CE 导入 → Univer 模型 → ExcelJS 导出」管道，导出文件与原件做程序化 diff（数据/公式/样式抽样）。
- 验收标准：
  1. 数据与公式保真率 100%（公式缓存值正确，Excel 打开无 0 值/无 #REF）；
  2. 样式（字体/填充/边框/数字格式）与合并单元格保真率 ≥ 90%（按单元格计数）；
  3. 数据验证与批注保留；图表降级为图片/数据表且导出文件在 Excel 中可正常打开不报错；
  4. 输出保真度矩阵报告，明确 L1–L4 各级达标情况，作为 M2 的基线。
